# Security reporting

Report suspected vulnerabilities privately with [GitHub private vulnerability reporting](https://github.com/SeanShaffer88/ArchiveKit/security/advisories/new). Do not put exploit details, secrets, private paths, hardware identifiers or full memory dumps in a public issue. Include the affected release or commit, Windows build/architecture, impact, and a minimal synthetic reproduction. This route is for this maintained repository; upstream projects have their own reporting policies.

Current development code and the latest published preview are reviewed on a best-effort basis. A release or passing CI does not constitute a security audit, and no response-time or backport guarantee is offered. Coordinated fixes should be validated against the affected scope before public disclosure.

For ordinary bugs and build questions use this repository's Issues page. Redact account names and machine paths from logs; keep real user data out of reproductions.
